# Performance Baseline and Optimisation

**Project:** VV-FOOS · **Date:** 2026-09-01 · v1.0 Draft

Everything here is measured, not estimated. Bundle composition comes from decoding the production sourcemap and attributing generated bytes per source file. Timings are the median of five cold loads per configuration.

## 1. Starting point

One 652 kB chunk (182 kB gzip), no code splitting. A bd user who cannot see the ATS still downloaded it; the login page downloaded every module.

| Share | Source |
| :---- | :---- |
| 20.2% | react-dom |
| 15.5% | @supabase/auth-js |
| 13.3% | modules/recruit |
| 9.0% | realtime-js + phoenix |
| 8.3% | modules/sales |
| 5.4% | @dnd-kit/core |
| 3.9% | modules/intake |
| 3.5% | @supabase/storage-js |
| 0.8% | lucide-react |

lucide-react at 5 kB confirms per-icon tree-shaking works, so adopting it cost almost nothing.

## 2. Changes made

**Route-level code splitting.** `React.lazy` for the five module route groups and the dashboard. The Suspense fallback is a plain inline line of text inside the shell, per redesign prompt section 9, not a spinner or skeleton.

**Vendor chunking.** `manualChunks` separates `vendor-react` and `vendor-supabase` so an application edit does not invalidate the browser cache for either.

**An unused webfont removed.** `index.html` loaded Inter in three weights from Google Fonts as a render-blocking cross-origin request. Inter is referenced nowhere; the computed body font is Roboto. A leftover from the pre-redesign UI. Removing it also removed two preconnects.

**Pagination.** All seven list views now page at 20 rows. The candidate list previously rendered every row in one pass and is backed by 83 real profiles that grow with each import. CSV export still exports the entire filtered set.

## 3. Result

Login page, median of five cold loads:

| Build | Payload | localhost FCP | Fast-3G FCP |
| :---- | :---- | :---- | :---- |
| Single bundle | 185.9 kB | 136 ms | 1268 ms |
| Split | 120.7 kB | 136 ms | 960 ms |

65 kB smaller (down 35%) and 308 ms faster (down 24%) on a throttled connection. Identical on localhost, which is the honest reading: zero latency hides payload size entirely. That equivalence also corrected an earlier single-sample reading that looked like a regression and was noise.

16 JS chunks after splitting, and the 500 kB chunk warning is gone. Total assets 698 kB raw, 200 kB gzip, of which only 120.7 kB is on the critical path.

## 4. Ceilings not yet addressed

**`vendor-supabase` is 215 kB and loads eagerly.** `createClient` imports auth, realtime, storage and postgrest as one graph, so chunking changes caching but not what executes at boot. Splitting it needs a custom client assembled from sub-packages, which is invasive and risks breaking `SessionProvider`. Not attempted.

**`@dnd-kit/core` at 5.4%** now rides inside the lazy recruit and sales chunks rather than the entry, so the login page no longer pays for it. A further win would be lazy-loading the Kanban board itself within those modules.

**No compression or caching at the edge yet.** `vercel.json` sets immutable caching for hashed assets and `no-cache` for `index.html`, but nothing is deployed, so this is untested in production.

## 5. Guards committed

| Script | Checks |
| :---- | :---- |
| `scripts/check-contrast.mjs` | 14 token pairs against WCAG AA, exits non-zero on failure |
| `scripts/check-motion.mjs` | 220 ms budget, forbidden layout-property transitions, no motion on shell selectors, reduced-motion block present |
| `scripts/check-migrations.mjs` | Repository migrations against those applied to a database |
| `scripts/check-comments.mjs` | Dividers, commented-out code, restatement, density |

All four run in CI alongside lint, typecheck and build, plus a schema job that rebuilds from migrations on Postgres 17 and runs `validate.sql`.
